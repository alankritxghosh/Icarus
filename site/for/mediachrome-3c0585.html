answeredWhy does media-chrome treat only remote.state === 'connected' as casting?

Media-chrome treats only 'connected' as casting to prevent transient states like 'connecting' from being incorrectly identified as active casting. On iOS Safari, 'connecting' could get stuck, which would cause the mediaiscasting attribute to remain set and block control autohide for the entire session.

answeredWhy is the playback rate display rounded, and what did Safari do without it?

The playback rate display is rounded to two decimal places to prevent Safari's binary float-precision drift (e.g., returning 1.1499999999999999 for 1.15) from leaking into the UI. Without this rounding, the raw, imprecise value was being stringified into the playback rate button label, menu button label, aria-label, and menu items.

answeredWhy is the fullscreen button hidden for cloudflare-video on iOS?

The fullscreen button is hidden for <cloudflare-video> on iOS because iOS browsers do not allow iframe-based elements to enter fullscreen mode due to platform-level restrictions enforced by WebKit. Hiding the button improves the user experience by preventing the display of a non-functional control.

answeredWhat caused the memory leaks patched in PR #1273, and what was holding the references?

The memory leaks in PR #1273 were caused by failure to clean up DOM state ownership, keyboard shortcuts dialogs, media-time-range animations, and internal references like #isResizePending and focus/invoker refs upon component teardown. Additionally, stateOwners were being held in the mediaStore after the controller was disconnected.

answeredWhy are media container observers removed on disconnect in PR #1061?

Removing media container observers on disconnect is considered best practice to ensure proper cleanup, as elements may be held in memory while being moved in the DOM, offloaded in scroll containers, or detached by frameworks.

PR #1055 was reverted because the previous solution caused a split-second empty flicker when using a slotted poster image.
