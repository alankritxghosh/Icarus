answeredWhy does the YouTube seekTo command need the allowSeekAhead parameter, in PR #1722?

The allowSeekAhead parameter is required by the YouTube iframe API's seekTo() method to allow seeking to any position, including unbuffered content. Passing this parameter prevents the player from getting stuck in a "waiting" state or throwing errors when performing seek operations.

answeredWhy were stale HLS instance callbacks guarded in PR #1806?

PR #1806 was implemented to prevent crashes caused by non-null assertions on HLS instances that had been destroyed or replaced. It ensures that callbacks from stale instances are guarded and that the system handles cases where the HLS media element is unavailable.

answeredWhy did sub-second seek targets need preserving in PR #1824?

Sub-second seek targets were preserved to stop the system from treating every seek within the same floored second as the seekable boundary and to support seeking near the start of short media.

The Vimeo poster needed its aspect ratio preserved because the previous implementation forced every poster to a 1920x1080 aspect ratio, which caused portrait-mode videos to display incorrectly.

answeredWhy did Firefox need a backdrop-filter fallback for menu visibility in PR #1717?

Firefox required a backdrop-filter fallback because the backdrop-filter: blur(4px) property caused rendering bugs that made settings and chapters menus invisible, even though they were present in the DOM.

answeredWhy is whitespace normalized in text track content before parsing, in PR #1716?

Whitespace is normalized because the media-captions library requires clean content without leading or trailing whitespace to parse correctly. Without this normalization, indented template literals used for inline subtitle content cause the parser to fail with errors.

answeredWhy was useLayoutEffect used for hasMounted in PR #1751, and what race condition did it prevent?

useLayoutEffect was used to ensure the re-render that removes <source> elements happens synchronously before the browser paints, preventing a race condition where hls.js's removeSourceChildren() would otherwise remove those elements first and trigger a NotFoundError.

answeredWhy is the poster image fallback src set to undefined instead of an empty string, in PR #1328?

The poster image fallback src is set to undefined instead of an empty string to avoid a React warning that occurs when an empty string is passed to the src attribute, which can cause the browser to re-download the page. Additionally, undefined was chosen over null because null does not typecheck in this context.

Early usage of the chrome API was removed because it caused a 'ReferenceError: chrome is not defined' when running the app in Capacitor, as the API was being accessed immediately upon import regardless of the browser used.

Autoplay respects the user's reduced motion preference to align with accessibility best practices and user preferences. When enabled, the player prevents videos from autoplaying regardless of the autoplay attribute value.

answeredWhy was workerd added to the node exports in PR #1198?

The workerd key was added to the package's conditional exports so that Cloudflare Workers would use the server bundle instead of the browser bundle, which was causing errors during server-side rendering.

answeredWhat was the webpack parse error worked around in PR #842, and what caused it?

The webpack parse error involved the media-time-slider calculation, which the integrated webpack in React 18 could not parse. The error was caused by a specific CSS calc expression: min(calc(var(--media-buffered) / max(var(--media-duration), 1)), 1) * 10.

answeredWhy did the project migrate to JASSUB for ASS subtitle rendering in PR #810?

The project migrated to JASSUB because it handles rendering differently than JSSO, offering features like on-demand rendering for high/variable framerate videos, offscreen rendering to prevent main thread lag, and improved font and video resizing handling. Additionally, JASSUB is more efficient, resulting in a smaller library size and faster execution due to its compilation methods.

The migration was motivated by the original rollup build failing due to rollup-plugin-dts@6 choking on a declare global block, an issue which is correctly handled by the rolldown-plugin-dts used by tsdown.
