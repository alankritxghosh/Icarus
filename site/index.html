II · Too near the sun

The part nobody else demos

It tells you when it doesn't know.

Ask most assistants why a constant is set to a particular number and you will get a confident, plausible answer. You will not be told it was a guess. Icarus refuses instead — and the refusal is enforced by code, not by asking a model nicely.

III · The wings

How it works

01

Connect a repository

Sign in with GitHub and point Icarus at a repo. It indexes the source, the pull requests, and the issue discussions — 22 file types across ~17 languages.

02

Hold a key and ask

Hold Right Option anywhere on your Mac and speak, or press ⌘⇧I to type. An overlay appears over whatever you were doing.

03

Read the proof

Icarus speaks a one-line summary and puts the quoted evidence on screen, linked to the exact lines on GitHub. Or it tells you nobody recorded a reason.

IV · The wax

What it will not do

Stated plainly, because a tool that hides its limits is asking to be trusted rather than checked.

  • It does not write code for you. This is not a coding agent.
  • It cannot cite evidence it did not retrieve. That is enforced deterministically: every citation must resolve to genuinely retrieved evidence with a valid line range, or the answer is refused.
  • It will abstain more than you expect. If your team never wrote down why, Icarus cannot tell you why. It will say so rather than reconstruct a plausible story.
  • It is an alpha. Large repositories index slowly, and the app is not yet notarized by Apple — see the install note below.

V · What he carried

Your code

  • Your code is never used to train any model, and is discarded after each request.
  • A repository is indexed once and shared with the people who can already read it on GitHub — so a team gets one brain instead of one copy each. Nobody else can reach it.
  • Icarus asks GitHub on every request whether you can still read that repository, rather than keeping its own list of who works where. A list like that goes stale; GitHub does not. When someone's access is revoked there, they lose access here within five minutes.
  • One company's code and questions are never mixed with another's.
  • Questions are recorded against the repository they were asked about: the question, whether Icarus could answer it, and what it cited. That record is what produces the list of things your team needed to know and nobody had written down. Who asked is not recorded — this maps what your organisation hasn't documented, it does not track who asked what. Answers themselves are not stored.
  • Disconnecting a repository forgets your connection to it. It does not delete the shared index, because your colleagues may still be using it.
  • Private repositories are cloned with your own GitHub token, held in memory for the duration of the request only — never written to disk or logs.

Icarus currently requests GitHub's repo scope, which grants access to your private repositories broadly. A GitHub App with per-repository, read-only access is the planned replacement. Said here rather than buried.

VI · The descent

Install

Four steps, about two minutes. Icarus is not notarized by Apple — notarization requires a paid Developer ID this alpha does not have yet, so macOS cannot vouch for it. Rather than paper over that, every install path is below, along with the checksum, so you can verify what you downloaded yourself.

Get started · macOS, Apple Silicon · ~2 minutes

01

Install

Download the .dmg below, or use one of the terminal paths that follow.

02

Sign in

Open Icarus, click "Sign in with GitHub." Asks for your identity only — nothing else, yet.

03

Connect a repo

Type owner/repo and press Connect. Icarus indexes it — seconds to a few minutes.

04

Claude Code — one time

Open Icarus → Settings and click Connect. Approve Keychain access if macOS asks. Skip this if you don't use Claude Code.

Terminal — recommended

curl -fsSLO https://icarus-website-kappa.vercel.app/install.sh
less install.sh        # ~100 lines, half of them comments — read it
sh install.sh

Three steps rather than one, deliberately: piping a script from the internet straight into a shell means running code you have not read, and you have no reason to extend us that. Read it first — it verifies the disk image's checksum before installing anything, and refuses if it does not match.

If you use Claude Code, the script also connects Icarus to it as an MCP server, so your coding agent can ask about this repository's history without any further setup. It skips that silently if Claude Code is not installed, and leaves an existing icarus entry alone.

Why the terminal at all: a browser tags its downloads as quarantined, and that tag is what triggers the "unverified developer" dialog. curl does not tag them, so this path never meets it. To be plain about what that means — it skips the prompt, not a real inspection. macOS has not checked this app on either path.

Or with Homebrew

brew install --cask alankritxghosh/icarus/icarus
xattr -dr com.apple.quarantine /Applications/Icarus.app

Both lines are needed: Homebrew quarantines what it downloads and a cask cannot waive that for you, so without the second line macOS still refuses to open it. In exchange you get brew upgrade, a clean brew uninstall, and a checksum Homebrew verifies itself. The tap is public.

Or in one line, if you would rather

curl -fsSL https://icarus-website-kappa.vercel.app/install.sh | sh

Or the disk image, by hand

1.  Download Icarus.dmg below and open it
2.  Drag Icarus onto the Applications folder beside it
3.  Open Icarus. macOS says it "cannot be opened because Apple
    cannot check it for malicious software" — this is expected
4.  System Settings → Privacy & Security, scroll down, then
    click "Open Anyway" beside the Icarus message and confirm

If no "Open Anyway" button appears, open Terminal and run xattr -dr com.apple.quarantine /Applications/Icarus.app, then open Icarus normally. (On macOS 14 and earlier you can instead right-click Icarus → Open.)

SHA-256 of Icarus.dmg — c4d2837c847135823bd310a99f2662c71d957787d9b14490f97d8d33a69ec76e
Check yours with shasum -a 256 Icarus.dmg. This detects a corrupted or altered download; it is not a substitute for Apple's signature, and does not pretend to be.

After that first launch it opens normally. Microphone and speech permissions are requested the first time you hold the talk key; both can be declined and typed questions still work.

Stuck, or something behaved oddly? Email alankritghosh05@gmail.com. This is an early beta — reports of what broke are genuinely useful.

VII · A second pair of wings

The GitHub extension

Optional, and separate from the app. It puts Icarus on GitHub itself: select lines in a file, ask what they do or why they are there, and get the same cited answer — or the same honest "no one wrote this down" — without leaving the page.

It is not on the Chrome Web Store. That means installing it the developer way, and Chrome will keep reminding you it is a developer-mode extension for as long as it is installed. That warning is accurate and there is no way to remove it short of a store listing, so it is stated here rather than discovered later. 

1.  Download icarus-extension.zip below and unzip it
2.  Open chrome://extensions and turn on "Developer mode"
3.  Click "Load unpacked" and choose the unzipped folder
4.  Click the Icarus toolbar icon, then "Connect Mac app"
    (or "Sign in with GitHub" if you don't have the app installed)

It only acts on repositories you have already connected in Icarus, and only on file pages (github.com/owner/repo/blob/…). On anything else it does nothing at all. It reads the lines you select and sends them to the same brain the app talks to; it does not watch pages you have not asked it about.

SHA-256 of icarus-extension.zip — ef09faf4e5db1dfabfa924a7f1c845dab544e5558a21e6b6bdbd62da2f462e4f
Check yours with shasum -a 256 icarus-extension.zip. Unlike the app, the extension has no auto-update — a new version means downloading and loading it again.

VIII · What your agent cannot see

Claude Code, Cursor, Codex

A merged pull request leaves a commit. A refused one leaves nothing — so git log, git blame and your working tree are blind to every change your team already tried and closed. Your coding agent reads exactly those three things. Icarus reads the rest, and this is how the agent asks it.

Claude Code

Already done if you followed Get started — the installer registers Icarus with Claude Code for you. Settings shows the live status and can install or repair the connector after a manual/Homebrew install. To do it by hand: 

claude mcp add --transport stdio --scope user icarus -- /Applications/Icarus.app/Contents/MacOS/Icarus --mcp

--scope user installs it once for every project rather than per repository. Nothing else to configure: the app is the server, so there is no package to install and no credential to paste.

Cursor, Codex, anything else that speaks MCP

{
  "mcpServers": {
    "icarus": {
      "type": "stdio",
      "command": "/Applications/Icarus.app/Contents/MacOS/Icarus",
      "args": ["--mcp"]
    }
  }
}

Put that in your client's MCP configuration — .cursor/mcp.json for Cursor, .mcp.json for a project-scoped Claude Code setup.

Repair and permissions

Open Icarus → Settings. It detects the checkout-only development adapter, migrates that known legacy entry only after you click Repair, and never overwrites an unrelated server with the same name. Because the check runs while Icarus is visible, any Keychain prompt is visible too.

Three read-only tools: the recorded why behind a change, an explanation of specific lines, and structured context before a task. Each call names the repository it expects, and Icarus refuses if a different one is connected rather than answering about the wrong codebase — one repository at a time, switched in the app. It never edits your code and never opens a pull request.
