## DISQUALIFIED — yt-dlp forbids AI contributions outright

**Both yt-dlp entries are removed, found 2026-08-21 before any work started.**
`CONTRIBUTING.md` carries a section titled **NO AI / NO LLM POLICY**:

> "This project strictly forbids the usage of LLMs, agents, or any other AI
> tools for any kind of contribution."

The issue template itself makes the reporter tick *"I've read the NO AI / NO LLM
POLICY and understand I may be blocked from the repository if it is violated."*
Submitting an agent-built patch there risks a ban and would be a straightforward
breach of a stated rule, whatever the patch's quality.

**This check is now part of the pre-flight**, and it is cheap — read
`CONTRIBUTING.md` and grep for an AI policy before a single line is written:

    gh api "repos/OWNER/REPO/contents/CONTRIBUTING.md" -q .content | base64 -d \
      | grep -icE "no ai|no llm|ai-generated|generated by (an )?(ai|llm)"

Screened across the whole shortlist: yt-dlp is the only prohibition. `spec-kit`
matches the grep but in the opposite direction — it tells contributors to *have
an AI coding agent available*. The rest say nothing, which is permission by
silence rather than by policy, so attribution in the PR body stays the right
default.

## The pre-flight, now three checks

Today's two dead ends were both caught by checks costing seconds, and neither by
Icarus:

1. **Existing PR** — `gh api "search/issues?q=repo:OWNER/REPO+type:pr+<n>+in:body"`.
   Killed the uv fix AFTER it was built and verified: PR #21121 was already open
   with the same change.
2. **Comment claims** — read the issue's own comments. Catches "I'd like to work
   on this" and, on sqlite-utils #841, the maintainer's *"So don't let your agent
   work on this."*
3. **Maintainer intent** — is the behaviour deliberate, deferred, or wanted?
   That is what Icarus is for, and the one it currently answers best when the
   question names the issue.

## Repo-level filter that produced this list

- Merges outside PRs: ≥4 distinct non-owner authors in the last 40 merges
- Issue aged past ~2 weeks, unassigned, ≤6 comments, labelled a bug
- Tests runnable without a heavy toolchain build — today's Rust build cost 2m40s
  and a full disk; the Python repos cost seconds
- Excluded: awesome-lists, book/roadmap repos, and repos whose issue tracker is
  predominantly non-English, since a misread issue is worse than no PR
